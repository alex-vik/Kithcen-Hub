# Память reviewer — повторяющиеся паттерны проекта

## Приёмы проверки
- Работа приходит уже закоммиченной, `git status` чистый: границы записи смотреть по `git show --stat <коммиты задачи>`, а не только по status.
- Один коммит бывает на две задачи (B-00e/T-001, d4cb502): зону записи проверять по каждому файлу отдельно.
- Exit code test-command проверять с `set -o pipefail` (или без `| tail`), иначе видно только код tail.
- Страж границ (tests/arch/boundaries.test.ts) и D3 проверяются на копии: `git archive HEAD | tar -x -C <scratchpad>/repo`, симлинк node_modules, подложить нарушителей в src/, прогнать `npx vitest run tests/arch` и `tsc -p tsconfig.domain.json`.

## Повторяющиеся проблемы
- Файлы домена вне карты ADR-004 4.2 (B-00e: `src/domain/result.ts` под CommandResult). Проверять каждый новый файл src/domain по карте; нет в карте — пожелание architect дописать карту.
- Названия тестов расходятся с содержимым (B-00e: тест «реэкспорт из config.ts внутри config.ts» без реэкспорта). Сверять название it() с образцом.

## Принятые строгости (не замечание)
- Страж ловит `Date` как слово и спецификаторы в комментариях домена — так в ADR-004 9.3. `PlainDate`/`ZonedDateTime`/`startDate` не ловятся (нет границы слова).
- Пока идёт ревью, параллельно появляются неотслеживаемые файлы другой задачи (B-00e: tests/unit, tests/support от T-001 в 15:26). Вердикт фиксировать по HEAD-коммиту, чужие untracked называть в отчёте отдельно, по mtime.

## T-001 (catalog, 2026-10-06)
- Решения delivery-lead, принятые на переходе tests→impl (запись в журнале задачи), остаются без теста: tester уже отработал. Сверять журнал задачи с тестами (T-001: `{normPeriod: null}` → 'norm_period' без теста в K27).
- Поведение на краях быстро проверяется так: `node --experimental-strip-types <scratchpad>/probe.ts` с абсолютными импортами из src/domain. Не запускать `vitest --root /`: обходит всю ФС и виснет.
- Домен проверяет в рантайме только поля типа string (unit), а union-поля (writeOffType, NormPeriod.kind) — нет: `{kind:'month'}` даёт dailyMilli NaN. В API/B-01b нужна рантайм-проверка.
- `roundHalfAway(x*1000)` на двоичном double: около 2% половин с 4 знаками после запятой уходят вниз (4.0005 → 4000). Для г/мл/шт неважно, но правило «половина от нуля» выполняется не всегда.
- Устаревшие комментарии каркаса («логику пишет backend-dev») остаются после реализации. Проверять шапки файлов.
