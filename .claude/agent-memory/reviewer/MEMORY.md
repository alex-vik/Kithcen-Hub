# Память reviewer — повторяющиеся проблемы проекта

## Тесты
- Порядок по (occurred_at, seq): тестовые данные из критериев часто имеют seq, согласованный со временем, — тогда реализация «только по seq» проходит. Требовать кейс, где seq противоречит occurred_at (запись задним числом: чек, ретро-отпуск). Найдено в T-001 К18 (tests/domain/catalog.test.ts). Проверка: мутация в копии в scratchpad (node_modules симлинком) + `npx vitest run tests/domain`.
- Хелпер frozen() в тестах — Object.freeze поверхностный (комментарий говорит «глубокая»); для плоских объектов достаточно.

## Процесс / границы

Проверять файлы коммита по зонам: tests/ — tester, src/domain|server — backend-dev, docs/ и CLAUDE.md (с согласия владельца) — lead.

- Instant сравнивается как строка ISO (src/domain/catalog.ts isActive) — корректно только при фиксированном формате `YYYY-MM-DDTHH:mm:ss.sssZ` (src/domain/time.ts). Следить, что сервер нормализует время к этому формату.
- Параметры раздела 15 валидируются при сборке конфигурации (ещё не написана; main.ts, B-17) — домен их не проверяет (suggestPortion: 0 → Infinity). Проверить, когда появится сборка.
- updateProduct молча игнорирует unit/id в патче; смена единицы — только changeUnit. В API (B-17) следить, чтобы unit не терялся молча.
