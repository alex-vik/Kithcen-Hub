# ADR-002. СУБД и драйвер

- Статус: предложено
- Дата: 2026-10-06
- Backlog: B-00b. Вопрос: Q-01 (закрыт владельцем 2026-10-06: SQLite)

## Контекст

Журнал событий — единственный источник правды (BR-01), события не редактируются и не удаляются (BR-02). Объём: десятки событий в сутки, порядка 10–20 тыс. в год. Один процесс, один пользователь. Время хранится в UTC (NFR-14). Потеря журнала — потеря всей истории (NFR-13). СУБД выбрана владельцем — открыт только выбор драйвера.

## Варианты драйвера

| Вариант | Плюсы | Риски |
| --- | --- | --- |
| **`node:sqlite` (встроенный, `DatabaseSync`)** | Ноль зависимостей, нет нативной сборки; синхронный API; с Node 24.15 — Release Candidate, без флага; есть `backup()` | Не «Stable»: возможны мелкие изменения API; версия SQLite привязана к версии Node |
| `better-sqlite3` | Зрелый, быстрый, синхронный | Нативный аддон: при отсутствии готового бинарника под Node/архитектуру — сборка `node-gyp` (компилятор, Python) |
| `sql.js` / wasm | Без нативного кода | БД в памяти, запись на диск вручную — неприемлемо для журнала |
| libSQL-клиент | Удалённая реплика | Лишняя сущность для одного дома |

## Рекомендация

`node:sqlite`, спрятанный за модулем хранения `src/server/storage/` (ADR-004). Ни один другой модуль не импортирует драйвер — замена на `better-sqlite3` локальна (API почти совпадает).

Правила:

- Файл БД — путь из конфигурации (переменная окружения), по умолчанию `data/kitchen.sqlite`; в тестах — `:memory:`.
- При открытии: `journal_mode=WAL`, `synchronous=FULL` (объём мал, надёжность важнее), `foreign_keys=ON`, `busy_timeout`.
- Таблицы `STRICT`. Время — текст ISO-8601 UTC с `Z` (сортируется лексикографически).
- Таблица событий append-only на уровне БД: триггеры `BEFORE UPDATE` и `BEFORE DELETE` → `RAISE(ABORT)`. Это защищает BR-02 от ошибки в коде.
- Миграции — пронумерованные SQL-файлы в `src/server/storage/migrations/`, применяются при старте в транзакции, версия — `PRAGMA user_version`. Миграции не переписывают строки журнала.
- Схема событий и возможная проекция-кэш — ADR-003. Бэкап (`backup()` / `VACUUM INTO` вне сервера) — ADR-007.

## Последствия

- Требуется Node ≥ 24.15.0 (зафиксировано в `package.json`).
- Синхронный API: тело транзакции выполняется атомарно в цикле событий, гонок между запросами и фоновой задачей нет (ADR-005). При десятках событий в сутки блокировка цикла незаметна.
- Если `node:sqlite` поменяет API до «Stable» — правка в одном модуле.
- Smoke-тест проверяет доступность `node:sqlite` в раннере.
