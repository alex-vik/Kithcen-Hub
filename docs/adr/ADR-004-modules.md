# ADR-004. Модули и направление зависимостей

- Статус: предложено
- Дата: 2026-10-06
- Backlog: B-00d. Требования: NFR-16, NFR-14, BR-27

## Контекст

Симулятор (`tests/sim/`) прогоняет доменное ядро на месяцах синтетического времени — это возможно, только если домен не трогает БД, сеть и системные часы (NFR-16). Параметры раздела 15 спеки — конфигурация, а не константы. Агенты пишут в разные каталоги (`backend-dev` — `src/domain/`, `src/server/`; `frontend-dev` — `src/web/`), поэтому границы модулей совпадают с границами записи.

## Варианты

1. **Функциональное ядро + императивная оболочка.** Домен — чистые функции над данными; сервер читает журнал, берёт время из часов, вызывает домен, пишет результат.
2. **Гексагональная архитектура с портами в домене.** Домен вызывает репозитории через интерфейсы. Тестируемо, но домен становится оркестратором ввода-вывода — для симулятора лишний слой подделок.
3. **Логика в обработчиках HTTP.** Быстро, но симулятор невозможен.

## Рекомендация

Вариант 1.

| Модуль | Содержит | Может импортировать |
| --- | --- | --- |
| `src/domain/` | Типы событий и позиций, остаток, автосписание, прогноз, калибровка, статусы, список покупок, сутки по Вильнюсу. Вход — события, состояние позиции, параметры, `now: Instant` / `day: LocalDate`. Выход — значения или новые события как данные | ничего (только стандартная библиотека JS и `Intl` с явным поясом) |
| `src/server/storage/` | SQLite-адаптер (ADR-002): дописать события, прочитать журнал, миграции, проекция-кэш, если её выберет ADR-003 | `domain` (типы) |
| `src/server/app/` | Сценарии: прочитать → `clock.now()` → домен → записать в одной транзакции | `domain`, `storage`, `clock` |
| `src/server/http/` | Маршруты, разбор и проверка формы запроса, отображение в типы контракта. Без доменных правил | `app`, `contract` |
| `src/server/jobs/` | Планировщик фоновых задач (ADR-005) | `app`, `clock` |
| `src/server/clock.ts` | Интерфейс `Clock`; реальная и поддельная реализации | `domain` (типы) |
| `src/server/main.ts` | Сборка: конфигурация, БД, часы, HTTP, задачи | всё в `src/server` |
| `src/contract/` | Типы запросов и ответов API, без логики. Пишет architect | ничего |
| `src/web/` | PWA | только `contract` |

Правила для домена: нет `Date.now()`, `new Date()` без аргумента, `Math.random()` (случайность — через параметр-генератор), нет `process.env`, `node:*`, ввода-вывода. Параметры раздела 15 приходят одним типизированным объектом конфигурации.

Модель журнала, форма событий, «значения-события» (инвентаризация, «закончилось»), отмена и порядок событий — **будет определено в ADR-003**. Этот ADR фиксирует только, что всё перечисленное — функции `src/domain/`, а хранение — `src/server/storage/`.

Симулятор импортирует `src/domain/` напрямую; сценарные тесты сервера — `app` с `:memory:`-БД и поддельными часами.

## Последствия

- Доменные тесты не требуют БД и выполняются за миллисекунды — симулятор годами времени остаётся быстрым.
- Вычисленные значения (остаток, прогноз, статус) веб получает от сервера; дублирования доменной логики в `src/web/` нет.
- Направление зависимостей проверяется архитектурным тестом в `tests/arch/` (разбор `import` в `src/`) — задача для tester, предлагаю отдельной меткой шага 1.
- Изменение контракта — только через architect: экраны и сервер не расходятся молча.
