# ADR-004. Модули и направление зависимостей

- Статус: принято (владелец, 2026-10-06)
- Дата: 2026-10-06
- Backlog: B-00d. Требования: NFR-16, NFR-14, BR-27, BR-26, FR-LOG-03
- Опирается на: ADR-002 (драйвер), ADR-003 (модель журнала, отмена, порядок, журнал состояний, идентификаторы)

## Контекст

Симулятор (`tests/sim/`) прогоняет доменное ядро на месяцах синтетического времени — это возможно, только если домен не трогает БД, сеть и системные часы (NFR-16). Параметры раздела 15 спеки — конфигурация, а не константы. Агенты пишут в разные каталоги (`backend-dev` — `src/domain/`, `src/server/`; `frontend-dev` — `src/web/`), поэтому границы модулей совпадают с границами записи.

## Варианты

1. **Функциональное ядро + императивная оболочка.** Домен — чистые функции над данными; сервер читает журнал, берёт время из часов, вызывает домен, пишет результат.
2. **Гексагональная архитектура с портами в домене.** Домен вызывает репозитории через интерфейсы. Тестируемо, но домен становится оркестратором ввода-вывода — для симулятора лишний слой подделок.
3. **Логика в обработчиках HTTP.** Быстро, но симулятор невозможен.

## Рекомендация

Вариант 1.

| Модуль | Содержит | Может импортировать |
| --- | --- | --- |
| `src/domain/` | Типы событий остатка и событий состояния, свёртка и лента остатка, активность позиции, лента журнала действий, автосписание, прогноз, калибровка, статусы, список покупок, сутки по Вильнюсу, строки-ключи производных `id`. Вход — события, параметры, `now: Instant` / `day: LocalDate`. Выход — значения или новые события как данные | ничего (только стандартная библиотека JS и `Intl` с явным поясом) |
| `src/server/storage/` | SQLite-адаптер (ADR-002): две append-only таблицы — события остатка и события состояния позиции; дописать, прочитать упорядоченно, проверить ссылку отмены, миграции. Проекции-кэша в первой версии нет (ADR-003, раздел 3) | `domain` (типы) |
| `src/server/app/` | Сценарии: прочитать → `clock.now()` → домен → ключ → UUIDv5 (`node:crypto`) → записать в одной транзакции | `domain`, `storage`, `clock` |
| `src/server/http/` | Маршруты, разбор и проверка формы запроса, отображение в типы контракта. Без доменных правил | `app`, `contract` |
| `src/server/jobs/` | Планировщик фоновых задач (ADR-005) | `app`, `clock` |
| `src/server/clock.ts` | Интерфейс `Clock`; реальная и поддельная реализации | `domain` (типы) |
| `src/server/main.ts` | Сборка: конфигурация, БД, часы, HTTP, задачи | всё в `src/server` |
| `src/contract/` | Типы запросов и ответов API, без логики. Пишет architect | ничего |
| `src/web/` | PWA | только `contract` |

Правила для домена: нет `Date.now()`, `new Date()` без аргумента, `Math.random()` (случайность — через параметр-генератор), нет `process.env`, `node:*`, ввода-вывода. Параметры раздела 15 приходят одним типизированным объектом конфигурации.

Что из ADR-003 где живёт:

| Из ADR-003 | Домен (`src/domain/`) | Хранение (`src/server/storage/`) и сценарии (`src/server/app/`) |
| --- | --- | --- |
| Остаток (разделы 3, 5) | Свёртка `stockBalance` и лента `stockTimeline` по списку событий позиции: значения-события, исключение отменённых, порядок `(occurred_at, seq)`, границы `asOf` и `recorded_at ≤ T` параметрами | Отдаёт события позиции, упорядоченные по `(product_id, occurred_at, seq)`. `SUM` в SQL не считает. Кэша нет; если сработает условие раздела 3, кэш появится здесь дополнением к ADR-003 |
| Отмена (раздел 6) | Определяет действующие события | Проверяет при записи, что цель существует и относится к той же позиции. Это проверка ссылки, не запрет по остатку |
| Журнал состояний позиции (раздел 7) | Активность — по последнему событию состояния; журнал действий FR-LOG-03 — объединение двух лент по времени | Отдельная append-only таблица событий состояния рядом с журналом остатка. Не входит в свёртку остатка |
| Идентификаторы (раздел 8) | Формирует строки-ключи производных `id` (`auto_writeoff:…`, `absence_cancel:…`, `auto_archive:…`). `id` для домена — непрозрачная строка | `app` переводит ключ в UUIDv5 через `node:crypto` и пишет «вставить, если такого `id` нет»; клиентский UUID приходит из `http` как есть. Ключи строк операций (`operation_line:…`) `app` формирует из `operation_id` и номера строки |
| Время | Получает `now` и границы параметрами | `recorded_at` = `clock.now()` передаёт `app`, `seq` присваивает хранилище при вставке |

Симулятор импортирует `src/domain/` напрямую; сценарные тесты сервера — `app` с `:memory:`-БД и поддельными часами.

## Последствия

- Доменные тесты не требуют БД и выполняются за миллисекунды — симулятор годами времени остаётся быстрым.
- Вычисленные значения (остаток, прогноз, статус) веб получает от сервера; дублирования доменной логики в `src/web/` нет.
- Направление зависимостей проверяется архитектурным тестом в `tests/arch/` (разбор `import` в `src/`) — задача для tester, предлагаю отдельной меткой шага 1.
- Изменение контракта — только через architect: экраны и сервер не расходятся молча.
