## Контекст

Владелец закрыл Q-06: TypeScript целиком — домен, сервер, PWA. Осталось выбрать рантайм, HTTP-фреймворк, сборщик клиента, тест-раннер и менеджер пакетов, а также зафиксировать структуру репозитория и одну команду, запускающую все тесты (её читает Stop-хук `.claude/hooks/require-green-tests.sh`).

Ограничения, которые определяют выбор:

- Масштаб: один пользователь, 150–200 позиций, десятки событий в день (раздел 3 спеки). Производительность фреймворков роли не играет; важны простота и малое число зависимостей.
- Код пишут агенты, поддерживает один человек (C-02). Меньше инструментов — меньше мест, где что-то ломается.
- Домен — чистые функции, время передаётся параметром (NFR-16); сутки по Europe/Vilnius с учётом перехода на летнее время (BR-27, NFR-14). Нужна надёжная работа с часовыми поясами.
- Развёртывание — Docker (ВПС или Proxmox, Q-02 открыт). Нативные зависимости, требующие компиляции при установке, усложняют образ.
- Офлайна нет (NFR-04), но PWA должна устанавливаться и принимать веб-пуш (NFR-01, FR-NTF-07).

Версии проверены 2026-10-06 по реестру npm и nodejs.org (ссылки в конце).

## Варианты

### Рантайм

| Вариант | За | Против |
| --- | --- | --- |
| **Node.js 26** | Станет LTS 2026-10-28, поддержка до 2029-04-30. `Temporal` включён по умолчанию — сутки по Вильнюсу и DST без библиотек. `node:sqlite` в статусе release candidate. Запуск `.ts` без сборки (type stripping стабилен) | До 2026-10-28 (три недели) — ветка Current |
| Node.js 24 | Active LTS сегодня | С 2026-10-20 — Maintenance, конец поддержки 2028-04-30. Нет `Temporal` — нужен полифил или самописная арифметика поясов |
| Bun / Deno | Встроенный TS, быстрый старт | Дальше от экосистемы агентов и Playwright (вторая фаза), меньше предсказуемость для одного поддерживающего |

### HTTP-фреймворк

| Вариант | За | Против |
| --- | --- | --- |
| **Hono 4 + @hono/node-server** | Маленький, без зависимостей, на стандартных `Request`/`Response`. `app.request()` гоняет запросы без сети — приёмочные тесты через API без поднятия порта. Типизированный клиент `hc` даёт общие типы клиенту и серверу | Моложе Fastify |
| Fastify 5 | Зрелый, `inject()` для тестов | Больше API и плагинов, чем нужно, схемы JSON Schema поверх TS-типов |
| Express 5 | Знаком всем | Нет встроенной типизации, тесты через supertest и сокет |

### Сборщик клиента и тест-раннер

| Вариант | За | Против |
| --- | --- | --- |
| **Vite 8 + Vitest 5** | Один конвейер трансформации для PWA и тестов, нулевая настройка TS, `vitest run` без watch | Vitest 5 вышел 2026-09-03 — свежий мажор |
| `node:test` + отдельный сборщик | Без зависимостей для тестов | Слабее матчеры и отчёты; клиенту всё равно нужен сборщик |
| Jest | Привычен | Отдельная трансформация TS, медленнее, хуже с ESM |

### Проверка типов

TypeScript 7.0 (нативный компилятор, `tsc` в пакете `typescript`) — только для `tsc --noEmit`. Исполнение не зависит от `tsc`: сервер запускается Node напрямую из `.ts`, тесты и клиент трансформирует Vite. Платформенный бинарник TS 7 ставится как optionalDependency (как esbuild) и нужен только в разработке, в образ не попадает.

### Менеджер пакетов

**npm** — идёт с Node, отдельной установки не требует. pnpm и yarn выигрывают на монорепо, которого здесь нет.

| Язык и проверка типов | TypeScript | 7.0.2 |
| HTTP | Hono + @hono/node-server | 4.13.13 / 2.1.3 |
| Сборка PWA | Vite | 8.3.3 |

Сервер запускается без шага сборки: `node src/server/main.ts`. Отсюда ограничения на синтаксис — только стираемый TypeScript (`erasableSyntaxOnly`): без `enum`, `namespace` с кодом, параметров-свойств конструктора и декораторов; относительные импорты с расширением `.ts`; импорт типов через `import type` (`verbatimModuleSyntax`).

UI-библиотека для PWA в этом ADR не выбирается: до шага 6 она не нужна, а выбор зависит от устройства киоска (Q-21, NFR-10). Решение — дополнением к ADR-001 перед B-23.

### Структура репозитория

Каталоги совпадают с границами записи агентов (`CLAUDE.md`, `.claude/hooks/guard-paths.sh`). Подробно модули — в ADR-004.

```
package.json, package-lock.json      architect (lock-файл обновляет npm)
tsconfig.base.json                   общие строгие опции
tsconfig.domain.json                 src/domain — без типов Node и DOM (чистота домена проверяется компилятором)
tsconfig.json                        src/domain, src/server, tests, конфиги — с типами Node
tsconfig.web.json                    src/web — с DOM
vite.config.ts                       сборка PWA из src/web
vitest.config.ts                     набор тестов
.claude/test-command                 одна строка — весь набор тестов
src/domain/                          backend-dev — чистый домен
src/server/                          backend-dev — HTTP, БД, планировщик
src/web/                             frontend-dev — PWA
src/smoke.test.ts                    architect — smoke шага 0 (см. ниже)
tests/                               tester — unit/, api/, sim/
docs/adr/                            architect
```

### Команда тестов

`.claude/test-command`:

```
npm test --silent
```

`npm test` = `vitest run && npm run --silent typecheck`. Сначала тесты (у тестировщика на стадии `tests` видны именно падения тестов), затем проверка типов всех трёх проектов. Без watch-режима и интерактива, код выхода 0 только если зелёно и то, и другое.

### Smoke-тест

`src/smoke.test.ts` — тривиальная проверка, что Vitest запускается и разбирает TypeScript. Лежит в `src/`, а не в `tests/`, потому что `tests/` — зона записи tester, а не architect. `vitest.config.ts` подключает этот файл явно и больше ничего из `src/` не собирает. Когда в `tests/` появятся настоящие тесты (шаг 1), tester может перенести smoke к себе; тогда architect уберёт его из `include`.

## Последствия

- Одна установка `npm install` даёт всё: рантайм-зависимостей у сервера две (`hono`, `@hono/node-server`), нативных нет. Docker-образ — `node:26-slim` с `npm ci --omit=dev`, без компиляторов.
- До 2026-10-28 Node 26 — Current. Риск минимален: LTS-статус меняет только политику поддержки, не API. Если окружение разработки на Node 24, всё, кроме `Temporal`, работает; код, использующий `Temporal`, требует 26.
- Разработчики не пишут `enum` и параметры-свойства; reviewer и `tsc` (`erasableSyntaxOnly`) это ловят.
- Домен проверяется отдельным `tsconfig.domain.json` без `@types/node` и DOM: импорт `node:*`, `process`, `setTimeout`, `window` в `src/domain` — ошибка компиляции. `Date.now()`, `new Date()`, `Temporal.Now`, `Math.random()` компилятор не ловит — их ловит reviewer (см. ADR-004).
- Vitest 5 и TypeScript 7 — свежие мажоры. Если в них найдётся блокирующая ошибка, откат на Vitest 4.1 / TypeScript 6.0 меняет только `package.json`.
- Lock-файл `package-lock.json` коммитится; `npm ci` в образе даёт воспроизводимую сборку.
- Пересмотр по Q-29 (2026-10-06): суточного автосписания больше нет, довод «Temporal для суток» ослаб, но не отпал — `Temporal` по-прежнему нужен для календарных дней по Вильнюсу в темпе и оценке остатка (BR-27, BR-29, BR-30) и для дней недели напоминаний (ADR-005); остальные доводы за Node 26 (LTS до 2029-04-30, `node:sqlite`) не изменились. Выбор остаётся.
