# ADR-001. Стек и структура репозитория

- Статус: принято (владелец, 2026-10-06)
- Дата: 2026-10-06
- Backlog: B-00a. Вопрос: Q-06 (закрыт владельцем 2026-10-06: TypeScript целиком)

## Контекст

Один пользователь, один дом, 150–200 позиций, десятки событий в сутки. PWA на одной кодовой базе (NFR-01), сервер с журналом событий, симулятор `tests/sim/`, гоняющий доменное ядро на годах синтетического времени (NFR-16). Разработчики не правят корневые файлы сборки — всё нужное для тестов, типизации и запуска должно быть заложено сейчас.

## Варианты

1. **Node.js + TypeScript, без шага сборки сервера.** Node сам удаляет типы при запуске `.ts` и даёт встроенный `node:sqlite` (ADR-002). TypeScript — только проверка типов (`noEmit`). Тесты — Vitest, PWA — Vite (Vitest уже тянет Vite).
2. **Bun или Deno.** Один бинарник: рантайм, тесты, SQLite. Минус — меньше зрелость экосистемы PWA-инструментов и Playwright-обвязки, второй рантайм в голове у агентов.
3. **Node + сборка `tsc` в `dist/` + Jest.** Классика, но лишний шаг сборки и медленный ESM/TS-путь у Jest.

## Рекомендация

Вариант 1.

| Что | Выбор |
| --- | --- |
| Рантайм | Целевой для продакшена — Node.js 24 LTS не ниже 24.15.0 (`.nvmrc` = `24`). Допустимый — `engines`: `^22.18.0 \|\| ^24.0.0`; на 22.x работают агенты и Stop-хук (см. «Версия Node») |
| Язык | TypeScript `^7.0.2`, `tsc --noEmit`; `erasableSyntaxOnly` — без `enum`, `namespace`, parameter properties; относительные импорты с `.ts` |
| Тесты | Vitest `^5.0.3`, один конфиг, `tests/**/*.test.ts`, включая `tests/sim/`; тесты идут с `TZ=UTC` |
| PWA | Vite + манифест/сервис-воркер — добавляется к шагу 6 отдельной правкой architect |
| HTTP | фиксируется вместе с API-контрактом (шаг 5); кандидат — встроенный `node:http` или Hono |
| E2E | Playwright — позже, к экранам |

Структура:

```
src/domain/    чистое ядро (ADR-004)
src/server/    хранение, HTTP, фоновые задачи, часы
src/contract/  типы API-контракта, общие для server и web
src/web/       PWA
tests/         тесты: tests/domain, tests/server, tests/sim, …
docs/          спека, ADR, задачи
data/          локальная БД (в .gitignore)
```

`.claude/test-command`: `npm test --silent` → `vitest run` по всему `tests/`. Проверка типов — `npm run typecheck`, в test-command не входит (см. последствия).

### Версия Node

Агенты и Stop-хук работают в контейнере с Node v22.22.0: `npm install`, `npm test` (4/4) и `tsc --noEmit` там проходят, `node:sqlite` работает с `ExperimentalWarning`. Продакшен — Node 24 LTS. Поэтому `engines` задаёт не целевую, а минимальную версию, на которой работает набор, а целевая — в `.nvmrc`.

Что нужно от рантайма и с какой версии это есть (по истории изменений в документации Node):

| Возможность | Ветка 22.x | Ветка 24.x | Источник |
| --- | --- | --- | --- |
| `node:sqlite` без флага `--experimental-sqlite` | 22.13.0 (Stability 1.1, `ExperimentalWarning`) | есть с 24.0.0 (с 23.4.0); Release Candidate (1.2) — с 24.15.0 | nodejs.org/docs/latest-v22.x/api/sqlite.html, nodejs.org/docs/latest-v24.x/api/sqlite.html |
| Удаление типов при запуске `.ts` по умолчанию | 22.18.0 (там же снято предупреждение) | есть с 24.0.0 (с 23.6.0); Stable — с 24.12.0 | nodejs.org/api/typescript.html |
| `sqlite.backup()` (для ADR-007) | 22.16.0 | не проверялось | nodejs.org/docs/latest-v22.x/api/sqlite.html |
| Vitest 5.0.3 | `^22.12.0` | `^24.0.0` (25.x не поддерживается) | `engines` пакета в npm registry |
| TypeScript 7.0.2 | `>=16.20.0` | — | `engines` пакета в npm registry |

Итог: `engines.node` = `^22.18.0 || ^24.0.0`. Нижняя граница 22.18.0 — удаление типов по умолчанию, это самое позднее из требований. Самим тестам оно не нужно, Vitest снимает типы сам. Нужно серверу: он запускается `node src/server/main.ts` без сборки. Ветки 23 и 25 исключены: они нечётные, без LTS, и Vitest 5 не поддерживает 25. Ветку 26 добавим, когда на ней проверим набор. В какой версии 24.x появился `sqlite.backup()`, не проверялось: это не важно, пока продакшен не ниже 24.15.0.

`.nvmrc` = `24`: nvm ставит последнюю 24.x. На 2026-10-06 документация ветки 24 описывает v24.21.0, это выше 24.15.0. Закрепить точную версию для продакшена — ADR-007.

## Последствия

- Тесты агентов идут на 22.x, продакшен — на 24.x. Код хранения пишется в пересечении API обеих веток (ADR-002). Перед выкладкой набор тестов прогоняется на продакшен-версии (ADR-007).
- `@types/node` сейчас `^24`: проверка типов пропустит API, которого нет в 22.x. Такая ошибка проявится только на 22.x и только в коде, покрытом тестами. Закрыть дыру — `@types/node` `^22` одной правкой `package.json`. Это вопрос оркестратору, в этой правке не сделано.
- Нет сборки сервера: `node src/server/main.ts` (точка входа появится на шаге 5).
- Stop-хук проверяет поведение, но не типы. Типы проверяет reviewer через `npm run typecheck`. Включить typecheck в test-command — одна строка, если оркестратор захочет.
- `lib` включает DOM для `src/web`; доменный код может случайно сослаться на DOM — ловится архитектурным тестом (ADR-004).
- Риск: TypeScript 7 и Vitest 5 — свежие мажорные версии. Откат — `typescript@^6`, `vitest@^4` без изменений в коде.
- Тесты не зависят от пояса машины; пояс дома задаётся явно (BR-27, NFR-14).
