# ADR-001. Стек и структура репозитория

- Статус: предложено
- Дата: 2026-10-06
- Backlog: B-00a. Вопрос: Q-06 (закрыт владельцем 2026-10-06: TypeScript целиком)

## Контекст

Один пользователь, один дом, 150–200 позиций, десятки событий в сутки. PWA на одной кодовой базе (NFR-01), сервер с журналом событий, симулятор `tests/sim/`, гоняющий доменное ядро на годах синтетического времени (NFR-16). Разработчики не правят корневые файлы сборки — всё нужное для тестов, типизации и запуска должно быть заложено сейчас.

## Варианты

1. **Node.js 24 LTS + TypeScript, без шага сборки сервера.** Node ≥ 24.15 сам удаляет типы при запуске `.ts` и даёт встроенный `node:sqlite` (ADR-002). TypeScript — только проверка типов (`noEmit`). Тесты — Vitest, PWA — Vite (Vitest уже тянет Vite).
2. **Bun или Deno.** Один бинарник: рантайм, тесты, SQLite. Минус — меньше зрелость экосистемы PWA-инструментов и Playwright-обвязки, второй рантайм в голове у агентов.
3. **Node + сборка `tsc` в `dist/` + Jest.** Классика, но лишний шаг сборки и медленный ESM/TS-путь у Jest.

## Рекомендация

Вариант 1.

| Что | Выбор |
| --- | --- |
| Рантайм | Node.js ≥ 24.15.0 (`engines`, `.nvmrc`) |
| Язык | TypeScript `^7.0.2`, `tsc --noEmit`; `erasableSyntaxOnly` — без `enum`, `namespace`, parameter properties; относительные импорты с `.ts` |
| Тесты | Vitest `^5.0.3`, один конфиг, `tests/**/*.test.ts`, включая `tests/sim/`; тесты идут с `TZ=UTC` |
| PWA | Vite + манифест/сервис-воркер — добавляется к шагу 6 отдельной правкой architect |
| HTTP | фиксируется вместе с API-контрактом (шаг 5); кандидат — встроенный `node:http` или Hono |
| E2E | Playwright — позже, к экранам |

Структура:

```
src/domain/    чистое ядро (ADR-004)
src/server/    хранение, HTTP, фоновые задачи, часы
src/contract/  типы API-контракта, общие для server и web
src/web/       PWA
tests/         тесты: tests/domain, tests/server, tests/sim, …
docs/          спека, ADR, задачи
data/          локальная БД (в .gitignore)
```

`.claude/test-command`: `npm test --silent` → `vitest run` по всему `tests/`. Проверка типов — `npm run typecheck`, в test-command не входит (см. последствия).

## Последствия

- Нет сборки сервера: `node src/server/main.ts` (точка входа появится на шаге 5).
- Stop-хук проверяет поведение, но не типы. Типы проверяет reviewer через `npm run typecheck`. Включить typecheck в test-command — одна строка, если оркестратор захочет.
- `lib` включает DOM для `src/web`; доменный код может случайно сослаться на DOM — ловится архитектурным тестом (ADR-004).
- Риск: TypeScript 7 и Vitest 5 — свежие мажорные версии. Откат — `typescript@^6`, `vitest@^4` без изменений в коде.
- Тесты не зависят от пояса машины; пояс дома задаётся явно (BR-27, NFR-14).
