# ADR-005. Фоновые задачи: автосписание, догон, сутки по Вильнюсу

- Статус: предложено
- Дата: 2026-10-06
- Backlog: B-00d. Требования: FR-CON-07, FR-CON-08, FR-ABS-03, FR-ABS-04, BR-27, NFR-07, NFR-14; параметр «Время автосписания» (раздел 15)

## Контекст

Автосписание — событие журнала, порождённое нормой (раздел о видах событий спеки). Выполняется раз в сутки после их окончания по местному времени; после простоя догоняет пропущенные сутки; повторный запуск за те же сутки ничего не меняет. Сутки — календарные в Europe/Vilnius; переход на летнее время (2026-03-29, 23 часа; 2026-10-25, 25 часов) не создаёт лишних и не теряет списаний.

## Варианты

1. **Cron на фиксированное местное время** (системный cron или `node-cron`). Пропускает запуски при простое; время 03:00–04:00 в дни перехода не существует или повторяется.
2. **Тик в процессе + догон по отметке обработанных суток.** При старте и периодически сервер вычисляет, какие завершённые сутки ещё не обработаны, и обрабатывает их по порядку.
3. **Без задач: автосписание вычисляется на лету при чтении.** Противоречит спеке — автосписание является событием журнала, и FR-ABS-04 отменяет уже выполненные списания.

## Рекомендация

Вариант 2. Без внешнего cron и без зависимостей.

- **Сутки — `LocalDate`** (`YYYY-MM-DD` в поясе дома), а не интервал в 24 часа. Перебор идёт по календарным датам; 23- и 25-часовые сутки — ровно одни сутки каждая.
- **Домен (чистые функции, время параметром):** границы суток `[начало, конец)` в UTC для `LocalDate` и пояса; список завершённых суток между последними обработанными и `now` с учётом параметра «время автосписания» (по умолчанию 00:00 следующего дня); расчёт списаний за сутки по позициям, нормам и отпускам (FR-ABS-03 — дни отпуска пропускаются). Пояс и время — из конфигурации. Часовые пояса — через `Intl` с явным `timeZone`, без библиотек.
- **Сервер `src/server/jobs/`:** тик при старте и каждые N минут (параметр конфигурации, по умолчанию 15). На тике для каждых необработанных суток по возрастанию: одна транзакция — домен считает списания, события дописываются, сутки отмечаются обработанными.
- **Идемпотентность (FR-CON-08):** таблица `job_runs(job, day)` с первичным ключом по обоим полям; дополнительно ключ идемпотентности у события автосписания (позиция + сутки). Повтор не меняет ничего ни при гонке, ни при ручном перезапуске.
- **Первый запуск:** точка отсчёта — сутки до установки; история назад не досписывается.
- **Длинный простой:** догоняются все пропущенные сутки, без ограничения — при 200 позициях это сотни строк (NFR-07).
- **Отпуск задним числом (FR-ABS-04):** отмена уже выполненных списаний — сценарий записи отпуска в `app`, а не задача планировщика. Форма отмены — будет определено в ADR-003.
- Тот же механизм (`job`, `day`) переиспользуют другие суточные задачи — очистка фото (NFR-18), бэкап (ADR-007).

## Последствия

- Синхронный драйвер (ADR-002): тело тика атомарно в цикле событий; флаг «тик идёт» защищает от наложения.
- Тесты — на поддельных часах: обычные сутки, обе даты перехода 2026 года, простой на неделю, двойной запуск, отпуск задним числом.
- Списание за сутки появляется в журнале не ровно в полночь, а в пределах N минут после неё — для однопользовательского дома незаметно.
- Предположение: «сутки до установки» как точка отсчёта — не задано в спеке; если владелец хочет иное, это вопрос, а не правка.
