# T-001 — Позиция каталога: единицы, пересчёт упаковок, порция, активность

## Контекст

Позиция каталога — то, для чего ведётся остаток. Задача даёт доменную модель позиции: расходная единица, торговая упаковка с коэффициентом, норма, порог, порция, ручная правка атрибутов и вывод активности из журнала состояний. На ней строятся журнал событий (B-02), автосписание, статусы и карточка продукта.

Задача только доменная: чистые функции и типы в `src/domain/` без БД, сети и часов (ADR-004, NFR-16). Хранение каталога и HTTP в задачу не входят: все критерии проверяются юнит-тестами домена.

## Бизнес-правила

- BR-03 — Остаток и норма ведутся в расходной единице. Приход в торговых упаковках пересчитывается через коэффициент.
- BR-04 — Разные размеры упаковки одного продукта (литр и пол-литра молока) — одна позиция. Различается только количество в событии прихода.
- BR-05 — Разная расходная единица означает разные позиции. Кофе в пачке (граммы) и кофе в капсулах (штуки) — две позиции каталога с отдельными нормами и остатками.
- BR-08 — Отключённая кнопкой и заархивированная по сроку позиция имеют одно состояние — «неактивна». Повод виден в журнале действий; отдельных состояний не вводится. *(В задаче — только форма состояния и его вывод; кто пишет события состояния — B-12.)*
- BR-10 — Система никогда не выставляет норму без подтверждения пользователя. *(В задаче — создание и правка позиции, предложение порции не заполняют норму.)*
- ADR-003, раздел 7 — признак активности не хранится флагом, а выводится из последнего по `(occurred_at, seq)` события журнала состояний позиции; нет событий — позиция активна.
- ADR-003, раздел 4 — количество в событии фиксируется в расходной единице в момент записи, поэтому правка коэффициента историю не переписывает. *(Проверяется в B-02.)*

## Модель позиции (для понимания критериев)

| Атрибут | Обязателен | Значение |
| --- | --- | --- |
| идентификатор | да | Передаётся вызывающим, домен его не генерирует |
| название | да | Непустая строка |
| категория | см. НВ-4 | Строка |
| тип списания | см. НВ-4 | ритмичный / рывковый / медленный или «не задан» |
| расходная единица | да | Из закрытого списка, см. НВ-3 |
| торговая упаковка | см. НВ-4 | Название упаковки (пачка, бутылка), строка |
| коэффициент пересчёта | см. НВ-4 | Расходных единиц в одной упаковке, конечное число больше нуля |
| норма | нет | Расход в расходной единице за сутки (НВ-1), больше нуля или пусто |
| нижний порог | нет | В расходной единице, не меньше нуля или пусто |
| размер порции | нет | В расходной единице, больше нуля или пусто |

Признака активности среди атрибутов нет: активность выводится из журнала состояний (К14–К16). Ожидаемый срок жизни упаковки (5.1) — атрибут медленных позиций, входит в B-12.

Имена функций и типов выбирают tester и backend-dev; критерии задают поведение. Проверки атрибутов карточки — не проверки остатка: инвариант 6 (BR-15) они не затрагивают.

## Критерии приёмки

### Создание и атрибуты (FR-CAT-01, BR-03, BR-10)

**К1. Позиция со всеми атрибутами.**
- Дано: название «Гречка», категория «Крупы», тип «рывковый», единица «г», упаковка «пачка», коэффициент 900, норма 30, нижний порог 300, порция 80
- Когда: создаётся позиция
- Тогда: результат — позиция, у которой все перечисленные атрибуты равны переданным; норма, порог и порция хранятся как числа в расходной единице позиции без собственной единицы измерения

**К2. Позиция с минимальным набором атрибутов.** `[НВ-4]`
- Дано: переданы только обязательные атрибуты (по ответу на НВ-4; по рекомендации — название, единица, упаковка, коэффициент)
- Когда: создаётся позиция
- Тогда: позиция создана; норма, нижний порог и порция пусты; тип списания «не задан»; категория пуста

**К3. Норма не заполняется системой.**
- Дано: позиция создаётся без нормы, но с порцией 10
- Когда: создаётся позиция, а затем запрашивается предложение порции (К11)
- Тогда: норма позиции пуста в обоих случаях

**К4. Недопустимые значения атрибутов отклоняются.**
- Дано: по отдельности — пустое название; коэффициент 0, −1, `NaN`, `Infinity`; единица не из списка НВ-3; норма 0 или −5; порог −1; порция 0
- Когда: создаётся позиция с таким значением
- Тогда: результат — ошибка с указанием атрибута, позиция не создаётся, исключение не выбрасывается

**К5. Граничные допустимые значения.**
- Дано: коэффициент 0,5; нижний порог 0
- Когда: создаётся позиция
- Тогда: позиция создана с этими значениями

### Ручная правка (FR-CAT-02, BR-03)

**К6. Правка любого атрибута.**
- Дано: позиция из К1
- Когда: по очереди правится каждый атрибут, кроме расходной единицы (её — К9), допустимым значением
- Тогда: в результате изменён только этот атрибут, остальные равны прежним; исходный объект позиции не изменился

**К7. Норму, порог и порцию можно очистить.**
- Дано: позиция из К1
- Когда: норма, порог или порция правятся на «пусто»
- Тогда: атрибут пуст, ошибки нет

**К8. Правка коэффициента не пересчитывает величины в расходной единице.**
- Дано: позиция из К1 (коэффициент 900, норма 30, порог 300, порция 80)
- Когда: коэффициент правится на 800
- Тогда: норма 30, порог 300, порция 80

**К8а. Правка недопустимым значением.**
- Дано: позиция из К1
- Когда: любой атрибут правится значением из К4
- Тогда: ошибка с указанием атрибута, позиция не изменилась

### Расходная единица (BR-05, FR-CAT-02) `[НВ-2]`

**К9. Смена единицы у позиции без событий остатка.**
- Дано: позиция с единицей «г»; вызывающий сообщает, что событий остатка по ней нет
- Когда: единица правится на «шт»
- Тогда: единица «шт», остальные атрибуты не изменились

**К10. Смена единицы у позиции с событиями остатка.**
- Дано: позиция с единицей «г»; вызывающий сообщает, что события остатка по ней есть
- Когда: единица правится на «шт»
- Тогда: ошибка «у позиции есть история — создайте новую позицию»; позиция не изменилась

**К10а. Разные единицы — разные позиции.**
- Дано: позиции «Кофе молотый» (г, норма 20) и «Кофе в капсулах» (шт, норма 2)
- Когда: у одной правятся норма, порог, порция, коэффициент
- Тогда: атрибуты второй не изменились; у каждой позиции ровно одна расходная единица

### Порция (FR-CAT-08) `[НВ-1]`

**К11. Предложение порции из нормы.**
- Дано: параметр «порций в суточной норме» = 1; позиция с нормой 20
- Когда: запрашивается предложение порции
- Тогда: предложено 20
- И: при параметре 2 предложено 10

**К12. Без нормы предложения нет.**
- Дано: позиция без нормы
- Когда: запрашивается предложение порции
- Тогда: результат — «нет предложения», а не 0 и не ошибка

**К13. Предложение не меняет позицию; ручная порция сохраняется.**
- Дано: позиция с нормой 20 и порцией 15, заданной вручную
- Когда: запрашивается предложение порции, затем норма правится на 40
- Тогда: порция остаётся 15; предложение (40 при параметре 1) возвращается отдельным значением и в позицию не записывается

### Пересчёт упаковок (BR-03, BR-04)

**К14. Упаковки в расходные единицы по коэффициенту позиции.**
- Дано: позиция «Гречка», коэффициент 900
- Когда: пересчитываются 2 упаковки
- Тогда: 1800

**К15. Другой размер упаковки — та же позиция.**
- Дано: позиция «Молоко», единица «мл», упаковка «бутылка», коэффициент 1000
- Когда: пересчитывается 1 упаковка с явным коэффициентом 500 (пол-литра)
- Тогда: 500; коэффициент позиции остаётся 1000, новая позиция не создаётся

### Активность из журнала состояний (ADR-003 §7, BR-08)

**К16. Нет событий состояния — позиция активна.**
- Дано: пустой журнал состояний позиции
- Когда: вычисляется активность
- Тогда: активна

**К17. Одно состояние «неактивна» при любом поводе.**
- Дано: последнее событие состояния — `inactive` с поводом `user_button`; во втором случае — `inactive` с поводом `auto_archive`
- Когда: вычисляется активность
- Тогда: в обоих случаях результат одинаковый — неактивна; других состояний функция не возвращает

**К18. Решает последнее событие по времени, а не по порядку в массиве.**
- Дано: события состояния переданы в перемешанном порядке: `inactive` (occurred_at 10.10 09:00, seq 1), `active` с поводом `purchase` (occurred_at 12.10 18:00, seq 3), `inactive` (occurred_at 11.10 12:00, seq 2)
- Когда: вычисляется активность
- Тогда: активна

**К19. При совпадении времени решает seq.**
- Дано: `active` и `inactive` с одинаковым occurred_at; у `inactive` seq больше
- Когда: вычисляется активность
- Тогда: неактивна; при обратном соотношении seq — активна

**К20. Параметры — из конфигурации.**
- Дано: объект конфигурации параметров раздела 15 (ADR-004) с параметром «порций в суточной норме»
- Когда: предложение порции вызывается с разными объектами конфигурации
- Тогда: результат зависит только от переданного объекта; числа 1 в логике предложения нет

## Не входит в задачу

- Журнал событий остатка, свёртка, приход в упаковках как событие, хранение `packs`/`units_per_pack` в событии и то, что правка коэффициента не переписывает историю — B-02.
- Отмена и идемпотентность — B-03.
- Кто и когда пишет события состояния: «больше не покупаю», автоархив, возврат покупкой и вручную, отмена изменения состояния, поиск неактивных, последствия BR-09 — B-12. Здесь только форма события состояния и вывод активности.
- Автоопределение типа списания по истории и его переопределение (FR-CAT-03), ожидаемый срок жизни упаковки медленных — B-12.
- Предложение нормы новой позиции, наблюдение, рассчитанная норма (FR-NEW-01…04, FR-CAT-07) — B-09. Первый запуск с типовыми нормами (FR-CON-04) — B-34.
- Статусы и использование нижнего порога (FR-STS-04) — B-10.
- Черновые позиции из чека, синонимы — B-20.
- Хранение каталога в SQLite и HTTP: в бэклоге каталог упомянут только в B-17 (API ядра). Если таблицу каталога нужно сделать раньше, это отдельная задача — решает оркестратор.
- Экран карточки продукта — B-29.
- Округление порции и количеств, отображение единиц — экраны.
- Уникальность названий в каталоге: спека её не требует, не проверяется.
- Всё из «Чего нет в первой версии»: сроки годности, места хранения, открытые/закрытые упаковки, стоимость.

## Открытые вопросы

Новые, в `docs/questions.md` пока нет. Нумерация «НВ» — внутренняя для этого черновика.

- **НВ-1. Норма за какой период и как из неё предлагается порция (FR-CAT-08).** Спека: норма — «расход за период», порция «предлагается из нормы». Варианты: (а) норма — суточный расход, порция = суточная норма / параметр «порций в суточной норме» (по умолчанию 1); (б) у нормы есть период (сутки, неделя, месяц), порция = норма за сутки / параметр; (в) порция не выводится, заполняется только вручную. Рекомендация — (а): автосписание суточное (FR-CON-01), ADR-003 считает норму в г/сут, FR-CON-05 («вторая чашка — отдельной кнопкой») значит, что порция ритмичной позиции — её суточная норма. Для рывковых норму в сутках задавать неудобно, но это вопрос B-08 (FR-CON-06), а не модели. Критерии К11–К13, К20.
- **НВ-2. Можно ли менять расходную единицу (FR-CAT-02 против BR-05 и инварианта 3).** «Все атрибуты редактируются» противоречит «разная единица — разные позиции»: история в граммах после смены на штуки становится бессмысленной. Варианты: (а) можно, пока по позиции нет событий остатка, иначе — создать новую позицию; (б) нельзя никогда после создания; (в) можно всегда, история пересчитывается коэффициентом — ломает инварианты 2–3. Рекомендация — (а): исправляет опечатку при заведении и не трогает историю. Критерии К9, К10.
- **НВ-3. Набор расходных единиц.** Спека приводит примеры: граммы, штуки, миллилитры. Варианты: (а) закрытый список г / мл / шт; (б) свободный текст. Рекомендация — (а): при свободном тексте «г» и «гр» стали бы разными единицами, и BR-05 перестал бы что-либо значить; килограммы и литры выражаются через коэффициент. Критерии К4, К9.
- **НВ-4. Какие атрибуты обязательны при создании.** Позиции появляются не только с карточки: из чека черновиком (FR-IN-08), тип списания система выставляет сама по истории (FR-CAT-03), то есть при создании его может не быть. Варианты: (а) обязательны название, единица, упаковка и коэффициент; категория, тип («не задан»), норма, порог, порция — необязательны; (б) обязательны только название и единица, коэффициент пуст до первой покупки в упаковках; (в) обязательны все атрибуты FR-CAT-01, кроме нормы и порога. Рекомендация — (а): без коэффициента нельзя пересчитать приход в упаковках (BR-03), а тип до накопления истории честно «не задан». Если для черновиков из чека коэффициент неизвестен, это решается в B-20 (Q-13). Критерии К2, К4.
