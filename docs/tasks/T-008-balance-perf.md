## Контекст

ADR-003 считает остаток свёрткой без кэша, пока остатки всех активных позиций на журнале 500 тыс. событий считаются не дольше 100 мс; «замер добавляется в симулятор (B-04)». Задача даёт этот замер и проверку, что путь через хранилище считает то же, что домен в памяти. Основная доля времени на сервере — чтение из SQLite, поэтому замер идёт и через хранилище.

## Решения (приняты delivery-lead 2026-10-07)

**НВ-4 (б).** Полный замер — отдельной командой `npm run perf` вне `.claude/test-command`: генерация и вставка 500 тыс. строк добавила бы к каждому прогону набора десятки секунд, а порог по времени на общем контейнере «мигает» и возвращал бы разработчиков Stop-хуком. В общем наборе `npm test` остаются К16 и К17 на уменьшенном журнале — проверка правильности без времени.

**Р2 (общее с T-007).** Каждое событие журнала создаётся через `createStockEvent`; отказ — падение с указанием события.

**Размещение — `tests/perf/`, вне `tests/sim/`** (предположение analyst, см. «Что нужно от architect»). Замеру нужны `src/server/` и `performance.now()`, а статическая проверка К3 (T-006) запрещает это во всём `tests/sim/`. Отдельный каталог не пересекается по файлам с T-006 и T-007.

## Бизнес-правила и требования

- ADR-003 §3 — условие ввести кэш: «На синтетическом журнале в 500 тыс. событий вычисление остатков всех активных позиций на целевом сервере занимает больше 100 мс».
- ADR-003 §1 — объём: 200 позиций, из них 60 ритмичных, не больше 5 000 событий на позицию.
- BR-01 — остаток вычисляется свёрткой журнала; хранилище не хранит остаток числом, путь (б) — те же события, та же `stockBalance`.
- BR-02 — отменённое событие исключается из расчёта; журнал содержит отмены, в том числе отмену отмены.
- `[Q-02]` — целевой сервер не выбран; замер в среде разработки — сигнал, а не окончательный вердикт.

## Критерии приёмки

Нумерация сквозная для T-006…T-008. Модуль, имена функций и форму вывода выбирает tester.

Объём журнала — параметр: в общем наборе `npm test` — уменьшенный, в `npm run perf` — полный (см. «Параметры»).

**К16. Синтетический журнал.**
- Дано: генератор с сидом и параметрами объёма (ADR-003 §1)
- Когда: генерируется журнал
- Тогда: 200 позиций, из них 60 ритмичных; число событий — целевое ± 1% (полный объём — 500 000, уменьшенный — 20 000); на позицию не больше 5 000; присутствуют все виды событий, включая `inventory`, `depleted` и `cancel` (в том числе отмена отмены); все события получены через `createStockEvent` с успехом; с тем же сидом журнал тот же, с другим — отличается
- И: в общем наборе — на уменьшенном объёме; в `npm run perf` — на полном

**К17. Остатки всех позиций: домен и хранилище дают одно и то же.**
- Дано: журнал К16 в памяти и тот же журнал, записанный во временную файловую БД через `openStorage` (T-004)
- Когда: остатки всех позиций считаются (а) `stockBalance` по событиям в памяти; (б) `listProducts` + `listStockEvents` по каждой позиции + `stockBalance`
- Тогда: остатки совпадают для всех 200 позиций
- И: в общем наборе — на уменьшенном объёме; в `npm run perf` — на полном, перед К18; временная БД удаляется после проверки

**К18. Порог ADR-003 §3 (только `npm run perf`).**
- Дано: БД К17 полного объёма открыта заново, выполнен прогрев (параметр)
- Когда: путь (б) из К17 выполняется N раз (параметр)
- Тогда: медиана ≤ 100 мс; в выводе — медиана и максимум для путей (а) и (б), версия Node и пометка «замер в среде разработки, не на целевом сервере (Q-02)»
- И: если порог превышен, проверка падает с текстом «сработало условие ADR-003 §3: нужен кэш» — это сигнал architect, а не дефект замера
- И: файлы К18 и полного объёма не попадают в `npm test` (общий набор не содержит проверок времени)

## Открытые вопросы

- **НВ-6. Откуда генератор журнала берёт случайность.** Детерминированный генератор с сидом создаётся в T-006 (К3, `tests/sim/`). T-008 должна идти параллельно с T-006, а два агента не правят один файл.
  - (а) T-008 начинается после того, как в T-006 сдан генератор К3, и импортирует его из `tests/sim/` (импорт в эту сторону К3 не нарушает).
  - (б) Свой минимальный генератор с сидом в `tests/perf/` — полная параллельность ценой дубля в несколько строк.
  - (в) Журнал строится без случайности, по детерминированной формуле от номера позиции и номера события; «сид» тогда — смещение формулы.

  Рекомендация — (а): T-008 всё равно ждёт скрипт architect, генератор К3 — первый и самый маленький кусок T-006, а дубль противоречит правилу «минимум кода». Если важна полная параллельность с первого дня — (б).
