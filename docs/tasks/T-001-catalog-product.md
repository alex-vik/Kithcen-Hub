## Контекст

Позиция каталога — то, для чего ведётся остаток. Задача фиксирует, из чего состоит позиция, как её создать и поправить вручную, как количество в упаковках переводится в расходную единицу и как норма, введённая за удобный период, переводится в суточную, чтобы журнал (B-02) и автосписание (шаг 3) с первого дня работали в одной единице. Задача — доменная: чистые функции без базы, сети и часов (NFR-16).

## Бизнес-правила

- BR-03 — Остаток и норма ведутся в расходной единице. Приход в торговых упаковках пересчитывается через коэффициент.
- BR-04 — Разные размеры упаковки одного продукта (литр и пол-литра молока) — одна позиция. Различается только количество в событии прихода.
- BR-05 — Разная расходная единица означает разные позиции. Кофе в пачке (граммы) и кофе в капсулах (штуки) — две позиции каталога с отдельными нормами и остатками.
- BR-10 — Система никогда не выставляет норму без подтверждения пользователя (инвариант 5; здесь — в части «создание и правка позиции не заполняют норму сами»).
- Глоссарий «Норма» (спека 1.4), решение Q-29 (закрыт) — норма хранится в расходных единицах в сутки; пользователь задаёт её за выбранный период (сутки, неделя, N дней), система пересчитывает в сутки; выбранный период и введённое за него количество хранятся у позиции для показа (решение delivery-lead: показ без обратного пересчёта, иначе 35714 × 7 = «249,998 г в неделю»).
- FR-CAT-08 (спека 1.4), решение Q-30 (закрыт) — порция по умолчанию равна суточной норме и следует за ней, пока не задана вручную; для «шт» округляется до целого, не меньше 1; ручная порция важнее; без нормы порции нет.
- Решение Q-28 (закрыт) — все количества в расходной единице хранятся целыми тысячными долями (`Milli`), округление до тысячной — один раз, при пересчёте ввода (ADR-002, 8.3).

Решения delivery-lead по вопросам аналитика (2026-10-06), на которые опираются критерии:

- Расходная единица — закрытый набор «г», «мл», «шт».
- Обязательны название и расходная единица; торговая упаковка и коэффициент задаются вместе или оба пусты; тип списания может быть пуст.
- Коэффициент, норма, порция — строго больше нуля; нижний порог — не меньше нуля. Это проверка ввода карточки, инвариант 6 (минус в остатке) не затрагивается.
- Категория — необязательный свободный текст. Название не уникально.
- Округление до тысячной — к ближайшему, половина — от нуля.

Связанные, но не реализуемые здесь: BR-08, BR-09 (неактивность — B-12), BR-01, BR-02 (журнал — B-02, B-03).

## Термины задачи

- **Количество** — целое число тысячных долей расходной единицы. 1,5 яйца = 1500; 250 г = 250000.
- **Период нормы** — один из вариантов: «сутки» (1 день), «неделя» (7 дней), «N дней» (N — целое, больше нуля).
- **Введённая норма** — количество и период ровно в том виде, в каком их задал пользователь (250 г, «неделя»); хранится для показа, в расчётах не участвует.
- **Суточная норма** — норма в тысячных долях расходной единицы в сутки: введённое количество, делённое на длину периода в днях, с одним округлением до тысячной.
- **Команда** — чистая функция «вход → результат или отказ». Отказ — значение с кодом ошибки, а не исключение (ADR-004, 4.3).
- **Эффективная порция** — порция, которую снимет «съел порцию»: заданная вручную, а если не задана — порция по умолчанию из суточной нормы.
- Пометка `[ВА-N]` — критерий записан по рекомендации аналитика к открытому вопросу ниже; до решения оркестратора может поменяться.

## Критерии приёмки

### Создание позиции

**К1. Минимальная позиция.**
- Дано: название «Гречка» и расходная единица «г»; остальные атрибуты не переданы.
- Когда: выполняется команда создания позиции.
- Тогда: результат успешен; позиция активна; название и единица — переданные; категория, тип списания, торговая упаковка, коэффициент, норма, период нормы, нижний порог и порция пусты.

**К2. Полная позиция (FR-CAT-01, FR-CAT-08).**
- Дано: название «Кофе молотый», категория «Напитки», тип «ритмичный», единица «г», упаковка «пачка», коэффициент 250 г, норма 30 г за период «сутки», нижний порог 100 г, порция 15 г.
- Когда: выполняется команда создания.
- Тогда: позиция содержит все переданные значения; коэффициент = 250000, суточная норма = 30000, период нормы — «сутки», порог = 100000, порция = 15000 тысячных долей грамма; позиция активна.

**К3. Норма не выставляется сама (BR-10).**
- Дано: создание позиции без нормы, но с коэффициентом и порцией.
- Когда: выполняется команда создания.
- Тогда: норма и период нормы в результате пусты; ни коэффициент, ни порция не превращаются в норму.

**К4. Допустимые расходные единицы.**
- Дано: единица из набора «г», «мл», «шт» — и, отдельно, единица «пачка».
- Когда: выполняется команда создания.
- Тогда: для «г», «мл», «шт» — успех; для «пачка» — отказ с кодом ошибки единицы, позиция не создана.

**К5. Обязательные поля.**
- Дано: пустое название (или строка из пробелов); отдельно — отсутствует расходная единица.
- Когда: выполняется команда создания.
- Тогда: отказ с кодом ошибки соответствующего поля; исключение не бросается.

**К6. Упаковка и коэффициент задаются парой.**
- Дано: указана торговая упаковка без коэффициента; отдельно — коэффициент без упаковки.
- Когда: выполняется команда создания.
- Тогда: в обоих случаях отказ с кодом ошибки упаковки.

**К7. Недопустимые количества.**
- Дано: по очереди — коэффициент 0, коэффициент −1, норма 0, порция 0, нижний порог −1.
- Когда: выполняется команда создания.
- Тогда: каждый случай — отказ с кодом ошибки поля. Нижний порог 0 — допустим.

### Норма за выбранный период (Q-29)

**К8. Пересчёт недельной нормы в суточную.**
- Дано: позиция «Кофе молотый», единица «г»; норма 250 г за период «неделя».
- Когда: выполняется команда создания.
- Тогда: суточная норма = 35714 (250000 / 7 = 35714,28… → 35714); введённая норма — 250000 за «неделя» сохраняется без изменений.

**К9. Пересчёт нормы за N дней.**
- Дано: позиция «Молоко», единица «мл»; норма 1000 мл за период «N дней», N = 2.
- Когда: выполняется команда создания.
- Тогда: суточная норма = 500000; введённая норма — 1000000 за «N дней», N = 2.

**К10. Одно округление, половина — от нуля.**
- Дано: позиция в «г»; по очереди — норма 0,003 г за «N дней», N = 2; норма 300 г за «неделя».
- Когда: выполняется команда создания.
- Тогда: 2 (3 / 2 = 1,5 → 2); 42857 (300000 / 7 = 42857,14… → 42857). Округляется частное от деления введённого количества на число дней, а не каждый шаг отдельно; результат всегда целое число.

**К11. Норма за сутки не пересчитывается.**
- Дано: норма 30 г за период «сутки».
- Когда: выполняется команда создания.
- Тогда: суточная норма = 30000; период — «сутки».

**К12. Недопустимый период.**
- Дано: по очереди — норма 250 г без периода; период «N дней» с N = 0; с N = −1; с N = 1,5; период без нормы.
- Когда: выполняется команда создания.
- Тогда: каждый случай — отказ с кодом ошибки периода нормы; позиция не создана.

**К13. Суточная норма округлилась до нуля (ВА-11, решение delivery-lead: отказ).**
- Дано: норма 0,001 г за «неделя» (1 / 7 = 0,14… → 0).
- Когда: выполняется команда создания.
- Тогда: отказ с кодом ошибки нормы (как для нормы 0 в К7); позиция не создана.

### BR-05: разная расходная единица — разные позиции

**К14. Две позиции «кофе».**
- Дано: создана позиция «Кофе» с единицей «г» и нормой 30 г за «сутки»; создана позиция «Кофе» с единицей «шт» и нормой 2 шт за «сутки».
- Когда: норма первой позиции правится на 40 г за «сутки».
- Тогда: обе позиции существуют как отдельные записи; у первой суточная норма 40000, у второй по-прежнему 2000; у каждой своя эффективная порция (40000 и 2000).

### BR-03, BR-04: пересчёт упаковок в расходную единицу

**К15. Целые упаковки.**
- Дано: позиция с коэффициентом 250 г на пачку.
- Когда: пересчитываются 2 упаковки.
- Тогда: результат — 500000 (500 г).

**К16. Другой размер упаковки — та же позиция (BR-04).**
- Дано: позиция «Молоко», единица «мл», упаковка «бутылка 1 л», коэффициент 1000 мл.
- Когда: пересчитывается 0,5 упаковки; отдельно — количество 500 мл, введённое прямо в расходной единице.
- Тогда: оба результата — 500000; позиция одна, её коэффициент не изменился.

**К17. Округление ввода до тысячной.**
- Дано: позиция в штуках с коэффициентом 10 шт на коробку.
- Когда: пересчитывается 1/3 коробки; отдельно — ввод 1,5 шт и 0,0005 шт в расходной единице.
- Тогда: 3333 (3,333 шт); 1500; 1 (половина округляется от нуля). Результат всегда целое число.

**К18. Пересчёт без коэффициента.**
- Дано: позиция без торговой упаковки и коэффициента.
- Когда: запрашивается пересчёт 1 упаковки.
- Тогда: отказ с кодом «у позиции нет упаковки»; исключение не бросается.

### FR-CAT-08: порция (Q-30)

**К19. Порция по умолчанию — суточная норма (г, мл).**
- Дано: позиция «Сыр», единица «г», норма 300 г за «неделя», порция не задана.
- Когда: запрашивается эффективная порция.
- Тогда: 42857 — равна суточной норме без дополнительного округления; сама позиция по-прежнему хранит порцию как не заданную.

**К20. Порция по умолчанию для «шт» — целая, не меньше 1.**
- Дано: позиции в «шт» без ручной порции, по очереди с нормой: 4 шт за «неделя» (суточная 571); 2 шт за «неделя» (суточная 286); 10 шт за «неделя» (суточная 1429); 3 шт за «N дней», N = 2 (суточная 1500); 3 шт за «сутки» (суточная 3000).
- Когда: запрашивается эффективная порция.
- Тогда: соответственно 1000; 1000 (округление дало бы 0 — поднимается до 1 шт); 1000; 2000 (половина — от нуля); 3000. Округление до целого делается от хранимой суточной нормы.

**К21. Порция по умолчанию следует за нормой.**
- Дано: позиция «Сыр» из К19; отдельно — позиция «Йогурт» в «шт» с нормой 4 шт за «неделя» без ручной порции.
- Когда: норма сыра правится на 700 г за «неделя»; норма йогурта — на 14 шт за «неделя».
- Тогда: эффективная порция сыра — 100000; йогурта — 2000; ручная порция у обеих по-прежнему не задана.

**К22. Ручная порция важнее нормы.**
- Дано: позиция «Кофе» в «г» с нормой 30 г за «сутки» и ручной порцией 15 г; позиция в «шт» с нормой 4 шт за «неделя» и ручной порцией 1,5 шт.
- Когда: запрашивается эффективная порция; затем норма первой правится на 40 г за «сутки», второй — на 14 шт за «неделя».
- Тогда: до и после правки эффективная порция — 15000 и 1500 соответственно; ручная порция не округляется до целого и не меняется правкой нормы.

**К23. Нет нормы — нет порции по умолчанию.**
- Дано: позиция без нормы и без порции.
- Когда: запрашивается эффективная порция.
- Тогда: результат «порции нет»; норма остаётся пустой (BR-10).

**К24. Сброс нормы убирает порцию по умолчанию, но не ручную.**
- Дано: позиция A с нормой 300 г за «неделя» без ручной порции; позиция B с нормой 30 г за «сутки» и ручной порцией 15 г.
- Когда: у обеих правкой сбрасывается норма.
- Тогда: у A эффективная порция — «порции нет»; у B — 15000; у обеих норма и период нормы пусты.

### FR-CAT-02: ручная правка

**К25. Каждый атрибут правится отдельно.**
- Дано: позиция из К2.
- Когда: для каждого атрибута по очереди — название, категория, тип списания, расходная единица, торговая упаковка вместе с коэффициентом, норма вместе с периодом, нижний порог, порция — выполняется команда правки с новым допустимым значением.
- Тогда: в результате изменён только этот атрибут; остальные, включая признак активности, совпадают с исходными. Правка нормы на 250 г за «неделя» даёт суточную норму 35714 и период «неделя», как при создании (К8).

**К26. Сброс необязательных атрибутов.**
- Дано: позиция из К2.
- Когда: правкой сбрасываются норма (вместе с периодом), нижний порог, порция, категория, тип списания; отдельно — упаковка вместе с коэффициентом.
- Тогда: каждый сброшенный атрибут пуст; отказа нет.

**К27. Неуспешная правка ничего не меняет.**
- Дано: позиция из К2.
- Когда: правка с недопустимым значением из К4–К7, К12, К13.
- Тогда: отказ с тем же кодом, что при создании; исходная позиция не изменена.

**К28. Правка не выставляет норму (BR-10).**
- Дано: позиция без нормы.
- Когда: правятся название, порция и коэффициент.
- Тогда: норма и период нормы остаются пустыми.

**К29. Активность не меняется общей правкой.**
- Дано: активная позиция.
- Когда: выполняется любая правка из К25.
- Тогда: позиция остаётся активной. Смена активности — отдельная команда B-12 с записью в `product_log`; команда правки её не принимает.

## Не входит в задачу

- **Хранение позиции** — B-01b: таблица `product` (миграция `0001`), открытие базы, раннер миграций, сервисы «создать / поправить / прочитать позицию», приёмочные тесты над базой `:memory:`, время создания позиции для ADR-005. Требования к будущей таблице уже заданы: `STRICT`, количества `INTEGER` с суффиксом `_milli`, `active INTEGER CHECK (active IN (0, 1))` (ADR-002, 8).
- **Смена расходной единицы у позиции с событиями** — открытый вопрос Q-31, проверка появляется вместе с журналом в B-02. В T-001 событий нет, поэтому правка единицы разрешена без условий; критериев про историю здесь нет.
- **Смена активности** («больше не покупаю», автоархив, возврат при покупке), `product_log`, BR-08, BR-09 — B-12. Автоархив FR-CAT-05 зависит от открытых Q-10 и Q-27.
- **Тип списания по истории** (FR-CAT-03, автоматическая часть) — B-12. Здесь тип только задаётся и правится вручную.
- **Ожидаемый срок жизни упаковки** для медленных (атрибут из 5.1, FR-CON-03) — B-12.
- **События и остаток**: запись прихода в упаковках как события, `meta` с числом упаковок и коэффициентом, свёртка, раздельные остатки двух позиций «кофе» (BR-01, BR-04 в части события прихода, BR-05 в части остатков) — B-02.
- **Вопрос размера порции при первом «съел порцию» без нормы** (Q-30) — экран и сценарий отметки, шаг 6. Здесь только результат «порции нет».
- **Форма ввода нормы и показ нормы в выбранном периоде** (обратный пересчёт «суточная × дни» и его округление при показе) — шаг 6, решения Q-29 и Q-28.
- Предложение нормы новой позиции и наблюдение за расходом (FR-NEW-01…04) — B-09.
- Поиск неактивных позиций (FR-CAT-06) — B-12 / API.
- Экран карточки — B-29. Округление количеств при показе — шаг 6 (решение Q-28).
- Пути модулей и имена функций — по ADR-004 после его принятия; критерии к ним не привязаны.
